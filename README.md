# Elk

Application de tâches, daily, journaux et analyse. Elle ne demande pas de compte, ne transmet pas les données à un serveur et ne dépend pas de bibliothèque externe. Le programme publié est générique ; la configuration personnelle et les données restent séparées. **Les sauvegardes sont indispensables.**

## Installation sur Android

Elk est une application web installable (PWA), pas un APK. Pour permettre son installation et son cache hors ligne, les navigateurs Android exigent une adresse **HTTPS** (ou `localhost`). Une simple copie ouverte comme fichier ne permet pas de garantir l’installation ni la conservation des données. La livraison de ce dossier ne publie pas l’application : il faut d’abord mettre ses fichiers statiques à disposition sur une adresse HTTPS. Aucun serveur de données ni abonnement n’est nécessaire, mais il vous faut choisir un hébergement HTTPS accessible au téléphone, éventuellement gratuit ; une adresse HTTP du réseau local ne suffit pas.

1. Publier uniquement les fichiers de l’application : `index.html`, `styles.css`, `sw.js`, `manifest.webmanifest`, les icônes et `src/core.js` avec `src/app.js`. **Ne publiez jamais** les sauvegardes JSON, le modèle personnel, ni les fichiers de listes et documents privés (`.txt` compris). Le code de l’application ne contient pas de configuration personnelle.
2. Sur le téléphone Android, ouvrir l’adresse HTTPS dans Chrome, attendre le chargement, puis choisir « Installer l’application » ou « Ajouter à l’écran d’accueil » dans le menu du navigateur.
3. Ouvrir Elk depuis son icône. Dans « Sauvegarde & données », importer le fichier modèle personnel. Vérifier le fonctionnement en activant le mode avion, puis désactiver ce dernier.
4. Exporter régulièrement une sauvegarde complète vers un emplacement privé distinct du téléphone. Tester sa restauration après avoir sauvegardé les données actuelles.

Chrome et Android peuvent supprimer les données locales, notamment après suppression de l’application, nettoyage du navigateur ou manque d’espace. Le modèle et les sauvegardes **ne sont pas chiffrés** : protéger l’appareil, choisir un emplacement privé et ne partager que les fichiers voulus. L’application n’offre ni synchronisation, ni notification, ni récupération automatique après effacement.

Pour tester sur un ordinateur équipé de Node.js, lancer `node tests\serve.js` depuis ce dossier, puis ouvrir `http://127.0.0.1:8765`. Ce serveur de développement n’est accessible que sur l’ordinateur et n’installe pas l’application sur le téléphone. Un simple `file://` est proposé uniquement comme essai sans garantie de persistance ni de cache hors ligne.

Le fichier `.gitignore` utilise une liste de fichiers publics autorisés : les autres fichiers restent exclus de Git par défaut. Avant tout premier commit, vérifiez `git status --short --untracked-files=all` et `git diff --cached --name-only`. Une règle d’exclusion ne retire pas les fichiers déjà suivis, n’empêche pas un ajout forcé (`git add -f`) et ne protège pas un dossier envoyé directement à un hébergeur : vérifiez toujours les fichiers publiés. Le serveur local ne sert que les ressources de l’application.

## Règles des tâches

- **Décompte** : après « C’est fait », la prochaine échéance est calculée à partir du jour de réalisation, même en avance ou en retard. Un report « C’est ok » relance immédiatement le décompte depuis aujourd’hui ; un report « Je suis en retard » déplace seulement l’échéance en cours.
- **Fixe** : les échéances restent attachées à la date de départ. Après réalisation, on reprend à la prochaine échéance de la série strictement après la réalisation et l’échéance courante : les créneaux passés sont sautés. Un report change uniquement l’échéance courante, quel que soit le motif. Pour une échéance annuelle exacte, le modèle peut porter un jour/mois (par exemple `05-21`) ; l’import calcule la prochaine occurrence et conserve cette date chaque année.
- Les occurrences hebdomadaires multiples sont espacées aussi régulièrement que possible en jours entiers, à partir de la date de départ. Les mois conservent le jour d’origine quand il existe, sinon le dernier jour du mois.
- Pour plusieurs fois par jour, chaque réalisation valide une occurrence, sans heure précise : les occurrences restantes conservent la même date. En mode décompte, « C’est ok » remet le quota à zéro pour le lendemain. Les réalisations en retard repartent du jour courant et les occurrences des jours antérieurs ne sont pas cumulées.
- Dans « Nouvelle tâche » ou « Modifier », renseignez le nom et la catégorie, puis le rythme et son fonctionnement, et enfin la prochaine échéance. Le repère annuel facultatif fixe le calendrier des prochaines occurrences et le recalage lors de l’import d’un modèle ; il ne remplace pas l’échéance en cours choisie dans le formulaire. Après cette échéance, le rythme reprend sur le calendrier du repère, y compris le 29 février en année bissextile. Sans repère, une modification du rythme, du fonctionnement ou de l’échéance démarre une nouvelle série ; modifier seulement le nom ou la catégorie conserve le cycle en cours. Les configurations et les actions restent dans l’historique ; l’archivage ne supprime pas les données.
- Une installation neuve commence sans tâches ni questionnaire. Importez un modèle personnel pour charger vos définitions ; les tâches configurées prennent comme première échéance la date d’import. Le modèle contient des définitions, jamais les réponses, journaux ou événements.

Les journaux de rêve et du soir ont chacun un titre et un texte. Sous le formulaire, les entrées enregistrées sont consultables en cartes datées, de la plus récente à la plus ancienne ; les anciennes entrées sans titre restent affichées comme « Sans titre ».

Les cycles annuel et mensuel montrent l’échéance actuelle et les **projections** des récurrences, calculées comme si chaque échéance était réalisée à sa date. Pour une tâche en retard, la projection suppose qu’elle est réalisée aujourd’hui. Elles ne sont pas enregistrées et peuvent changer après réalisation ou report. Les points clairs représentent les projections seules ; un point peut regrouper plusieurs échéances proches, accessibles en le touchant. Un petit trait sur les anneaux annuel et mensuel indique la position d’aujourd’hui dans la période affichée. L’année est glissante sur 12 mois ou commence le 1er septembre ; le mois est glissant sur 30 jours ou correspond au mois civil. Sur le cercle journalier, chaque tâche due aujourd’hui est répartie régulièrement, sans signification horaire. Les retards apparaissent dans la liste.

La vue d’ensemble et « Modifier les tâches » proposent des boutons on/off par catégorie, identifiés par emoji. Toutes les catégories sont activées par défaut. Dans la vue d’ensemble, le filtre s’applique aux cycles, aux échéances et au décompte des tâches ; dans la gestion, il filtre les tâches actives et archivées. Pour réduire le chevauchement, le cercle annuel ne montre que les rythmes d’au plus une occurrence par mois (en moyenne), le cercle mensuel ceux d’au plus une occurrence par semaine, et le cercle journalier toutes les tâches dues aujourd’hui. Les dates quotidiennes, hebdomadaires et bimensuelles restent accessibles dans la liste des tâches.

## Daily et analyse

L’auto-évaluation est définie par le modèle importé et s’ouvre dans une fenêtre dédiée. Chaque réponse est facultative et enregistrée à la validation de l’étape ; « Passer » laisse inchangées les réponses précédentes (sauf les champs configurés pour enregistrer zéro lorsqu’ils sont sautés). Les journaux du soir et de rêve alimentent automatiquement leurs indicateurs pour la date choisie.

Les retards calculés comptent les réalisations après échéance et les reports pour retard ; les avances comptent les réalisations avant échéance. Ce sont des **événements**, pas le nombre de tâches actuellement en retard : une même tâche peut contribuer plusieurs fois. L’analyse compare deux variables numériques par date ; elle ne remplace ni une interprétation personnelle ni un avis professionnel.

## Développement et mises à jour

Le code public est réparti entre `src/core.js` (dates, récurrences, événements, modèles et validation) et `src/app.js` (interface). Une nouvelle installation est vide. Depuis « Sauvegarde & données », exportez/importez le modèle personnel (définitions de tâches et Daily seulement) séparément de la sauvegarde complète. L’import présente un aperçu ; les tâches retirées sont archivées et l’historique, les réponses et journaux sont conservés. Une tâche modifiée par le modèle démarre une nouvelle série à la date d’import ; les tâches inchangées gardent leur échéance. Une sauvegarde complète de version inconnue est refusée.

Le schéma de sauvegarde est à la version 2 et utilise une clé locale dédiée. Les sauvegardes version 1 sont migrées à la restauration ; elles conservent tâches, historique, réponses Daily et journaux, mais ne contiennent pas les définitions du modèle Daily. Après restauration d’une sauvegarde v1, réimportez le modèle personnel pour retrouver les questions Daily. Les modèles version 1 restent importables ; la version 2 ajoute les repères annuels au format `MM-JJ`. Les dates limites des impôts sont publiées chaque année et peuvent dépendre du département ; l’URSSAF dépend du régime et de la périodicité. Vérifiez les échéances administratives de votre modèle auprès des organismes concernés. Incrémenter le nom du cache dans `sw.js` à chaque publication ; fermer puis rouvrir toutes les fenêtres Elk pour activer le nouveau service worker. Si le schéma évolue, ajouter une migration explicite et des tests de restauration avant de publier.

Tests sans dépendance : `node --test tests\core.test.js tests\serve.test.js`.
